Salah Archive v15.76 — تدقيق مرشح الربط قبل الاختبار الحقيقي
===========================================================

ما أُنجز في هذه الدفعة:
1) طبّقت MYSQL_RUNTIME_INTEGRATION.patch على نسخة منفصلة من main.py لإنتاج main_mysql_candidate_v15_76.py.
2) بقي main.py الأصلي دون تعديل، وبقي مطابقاً لبصمة manifest الموقعة.
3) اجتاز الملف المرشح فحص Python compile. ظهر تحذير قديم invalid escape sequence في نص JavaScript المضمّن قرب السطر 1061.
4) شغّلت اختبار بدء SQLite وعمليات الإضافة/القراءة/التعديل/الحذف داخل مجلد مؤقت مستقل؛ نجحت الاختبارات وحُذف المجلد المؤقت بعد انتهائها.
5) أضيفت اختبارات ثابتة للتحقق من فصل المرشح عن الملف الأصلي، وتقييد الاتصال إلى قاعدة الاختبار، وعدم الادعاء باختبار MySQL الحقيقي.

حدود مؤكدة:
- لم يحدث اتصال بخادم MySQL حقيقي.
- لم تُختبر واجهات الأرشفة/الماسح/المرفقات/الذكاء الاصطناعي عبر MySQL.
- main_mysql_candidate_v15_76.py مرشح غير موقّع رسمياً، ولا يستبدل main.py.
- قاعدة المستخدم الأصلية لم تُفتح أو تُعدّل.
- لا تستخدم أي ملفات ترحيل قديمة تحتوي DROP TABLE أو تغييرات غير مراجعة على قاعدة الإنتاج.

النتيجة: اختبار SQLite المنفصل ناجح، لكن اعتماد MySQL التشغيلي لا يزال BLOCKED حتى اختبار MySQL حقيقي على salah_archive_test ومراجعة نتائج CRUD والمرفقات والترحيل.
