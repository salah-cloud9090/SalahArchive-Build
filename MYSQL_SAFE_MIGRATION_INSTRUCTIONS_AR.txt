تعليمات فحص/ترحيل MySQL الآمن
============================

قبل التنفيذ:
1. لا تنفّذ الترحيل على قاعدة الإنتاج. هذه الحزمة تسمح فقط بقاعدة اسمها salah_archive_test.
2. أنشئ قاعدة اختبار فارغة ومستخدم اختبار محدود الصلاحيات باستخدام MYSQL_TEST_DATABASE_SETUP.sql بعد استبدال كلمة المرور الوهمية. لا تمنح المستخدم صلاحية DROP أو GRANT.
3. انسخ mysql_config.sample.json إلى mysql_config.json في مجلد الحزمة وعدّل host/user فقط. لا تضع كلمة المرور في JSON.
4. عيّن متغير بيئة Windows باسم SALAH_MYSQL_PASSWORD إلى كلمة مرور مستخدم الاختبار.
5. شغّل PREFLIGHT_MYSQL_TEST_SAFE.bat، وأدخل مسار docuware_archive.db الأصلي ومسار local_archive_files الصحيحين. راجع التقرير قبل أي تنفيذ.
6. فقط إذا كانت النتيجة DRY_RUN_PASS وكانت قاعدة الاختبار فارغة/بجداول مرشحة فارغة ومتوافقة، شغّل MIGRATE_TO_MYSQL_TEST_SAFE.bat.

سلوك أداة الترحيل:
- تتصل بقاعدة الاختبار فقط وتتحقق من اسم قاعدة البيانات قبل الكتابة.
- ترفض أي جدول غير متوقع أو جدول يحتوي بيانات مسبقاً.
- ترفض أعمدة مصدر لا يغطيها المخطط المرشح.
- تفحص وجود ملفات المستندات وتطابق SHA-256 والحجم قبل النسخ.
- تنشئ نسخة SQLite متسقة باستخدام Backup API قبل إنشاء مخطط MySQL.
- تنقل السجلات بترتيب يحترم العلاقات، ثم تقارن أعداد السجلات.
- لا تحتوي الأداة على DROP TABLE أو TRUNCATE ولا تحذف قاعدة SQLite الأصلية أو ملفاتها.

تنبيه بشأن إصدار البرنامج:
- main.py الأصلي بقي كما هو وبقي فحص سلامة ملفاته ناجحاً.
- ملف MYSQL_RUNTIME_INTEGRATION.patch اقتراح تعديل غير مطبّق وغير موقّع؛ لا تطبقه على نسخة البرنامج الرسمية حتى يراجعه صاحب مفتاح التوقيع ويعيد إصدارها.
- حتى نجاح الترحيل التجريبي لا يعني أن تشغيل التطبيق عبر MySQL معتمد؛ يلزم دمج patch وإعادة التوقيع ثم اختبار CRUD والبحث والأرشفة والمرفقات فعلياً على Windows مع MySQL.
